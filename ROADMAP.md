## 🟢 Фаза 1 — Стабилизация (1–2 месяца)
*Цель: устранить технический долг, сделать систему надёжной под нагрузкой*

### 1.1 Производительность
- [ ] **Пагинация API** — `/api/orders?page=1&limit=50`, `/api/tasks?order_id=X`
- [ ] **loadAll() → инкрементальные обновления** — SSE должен обновлять только изменённые записи, не всё
- [ ] **Индексы БД** — `tasks(operator)`, `scan_log(operator)`, `tasks(order_id, status)`
- [ ] **Кэш статичных данных** — детали и операции менялись редко, кэшировать в localStorage

### 1.2 Надёжность
- [ ] **SSE reconnect** — авто-переподключение при обрыве с exponential backoff
- [ ] **Offline-режим** — очередь действий при потере связи (сканирование в оффлайн)
- [ ] **Обработка ошибок** — единый ErrorBoundary на фронте, структурированный лог на бэке
- [ ] **Healthcheck endpoint** — `/api/health` для мониторинга

### 1.3 Безопасность
- [ ] **Автообновление SSL** — certbot renew в cron + автокопирование в Docker
- [ ] **JWT_SECRET из secrets** — Docker secrets или Vault вместо .env
- [ ] **Redis rate limiting** — вынести из MySQL
- [ ] **Аудит лог** — кто что изменил (изменение статуса заказа, редактирование)

### 1.4 Рефакторинг
- [ ] **Zustand/Context** — вынести стейт из App.jsx (26 хуков)
- [ ] **Разбить Modals.jsx** — 856 строк → отдельные файлы
- [ ] **Удалить Workshop.jsx** — дублирует WorkCenter, legacy
- [ ] **PHPUnit тесты** — минимум для OrdersController, TasksController, Auth
- [ ] **Vitest тесты** — unit-тесты для api-helpers, критических компонентов
